7.7 Deep dive: what exactly goes into the network

A neural network only sees numbers. Each camera frame becomes a stack of 48 × 64 arrays ("channels"), each scaled to the range 0–1 so that no channel dominates just because its units are larger:

red, green, bluecolour 0–255÷ 255 (already 0–1 from the renderer)colour, fused

Depth is in every detector for a reason: it tells the network how big an object really is. A warm blob 10 pixels wide is a small animal if it is 1 m away but a whole person if it is 4 m away. Temperature uses an absolute scale (a radiometric camera measures degrees), so 33 °C always maps to the same number, 0.58.

* Receptive field: how many input pixels, across, can influence one output. A dilated convolution with dilation d spaces its 3 taps d cells apart, so it adds 2·d·(current stride) pixels without adding weights. 72 pixels is more than the image's 64-pixel width: every output block can "see" the whole frame, which is what lets the network tell a 1.75 m body from a 0.75 m dog.

7.9 Training, in code

net = build_net(channels);  opt = AdamW(lr = 0.002, weight_decay = 1e-4);  schedule = cosine over 20 epochs
pos_weight = sqrt(min(20, (1 − p) / p))            # p = share of "person" blocks in the training labels
for epoch in 1..20:
    for each batch of 64 images (random order):
        if coin flip: mirror images and labels left-right          # augmentation
        loss = BCEWithLogits(net(images), labels, pos_weight)       # per 4×4 block
        loss.backward();  opt.step()                                 # gradient descent

Binary cross-entropy punishes confident mistakes most: predicting 0.99 for a block with no person costs −ln(0.01) = 4.6, predicting 0.6 costs 0.9. Because only a few percent of blocks show a person, each person block's loss is multiplied by pos_weight. If 3 % of blocks were positive, (0.97/0.03) = 32 would be capped at 20, giving √20 ≈ 4.5. The square root is a compromise: enough weight to stop the network ignoring people, not so much that every warm blob becomes a person. Cosine decay lowers the learning rate smoothly to zero over the 20 epochs, and AdamW adapts the step size per weight, with weight decay to keep the weights small (less over-fitting).

What the test scores mean

On the 4,000 unseen test images, 1,111 contain a visible person. Using the fused detector at a 0.5 threshold as an example:

  • Recall 98.3 %: of the 1,111 images with a person, about 1,092 are flagged. About 19 are missed (typically a person seen edge-on, far away or mostly hidden).
  • Precision 83 %: of all flagged images, 83 % really contain a person, so roughly 220 flags are look-alikes (dogs, warm rubble, bags).
  • ROC-AUC 0.994: pick one image with a person and one without; 99.4 % of the time the one with the person gets the higher score. It is independent of the threshold.
  • Heatmap average precision 0.993: the same idea per 4 × 4 block. It measures whether the network points at the right place, not just the right image.

Single-image precision of 83 % would be far too many false alarms to hand to rescuers. That is exactly why the robots use a higher threshold (0.92, not 0.5) and the belief filter: repeated close looks from several angles lift the reported precision to 88–89 % (chapter 14).

In simple words

The network is like a new rescuer who has studied 20,000 photos of collapsed rooms. They are good at spotting people, sometimes fooled by a dog in the dark, and never allowed to report a person after one glance. The team makes them walk closer and look again, from another side, until the evidence is overwhelming.

7.11 What ML does not do here, and why

  • It does not drive the robot. No reinforcement learning, no learned policy. Every decision in chapters 8–11 is an explicit, explainable rule, and the dashboard prints the reason for each one. This is a deliberate choice for a safety-critical task: you can always say why a robot did something.
  • It does not build the map. The occupancy grid is Bayesian evidence from LiDAR, camera and bumper.
  • It does not output bounding boxes. A heatmap suits this problem better. People lie in any orientation, are often partly covered, and several can be in one frame. A heatmap marks every visible body part, and the depth at the peak block places it on the map directly. A box detector such as YOLO would need anchor boxes, a much larger model and far more training data.
  • It has never seen a real photo. Trained only on simulated images, it would need real or domain-randomised data before use on a real robot (the sim-to-real gap, chapter 15).
  • It can be swapped. python -m rescue train retrains the detectors. Any other detector only has to return the same 12 × 16 heatmap from CNNDetector.heatmap, and nothing downstream changes.
