9Route planning

Once a goal is chosen, the robot needs a route: a chain of neighbouring free cells from where it stands to the goal. The project implements four planners that obey exactly the same rules (free cells only, 8 moves, straight 1 / diagonal 1.4142, no corner cutting), so their routes can be compared fairly.

9.1 The map as a graph

A planner sees the map as a graph: every free cell is a node, and every allowed move to a neighbour is an edge with a cost (1 or 1.4142, plus an optional extra cost per cell such as the revisit penalty of chapter 10). Finding the cheapest route is then the classic shortest-path problem.

9.2 Dijkstra (1959)

Dijkstra's algorithm grows the set of cells whose shortest distance is known, always taking the closest unfinished cell next. It uses a priority queue (a heap) ordered by g, the cost from the start:

g[start] = 0;  every other g = ∞;  heap = [(0, start)]
while heap not empty:
    (g_c, c) = pop the entry with the smallest g           # c's distance is now final
    if c is the goal: stop, and follow parent[] links back to the start
    for each allowed move c → n with cost k:
        if g_c + k < g[n]:  g[n] = g_c + k;  parent[n] = c;  push (g[n], n)

Why it is correct: all step costs are positive, so when a cell is popped with the smallest g, no later path can reach it more cheaply. Its distance is final. Dijkstra therefore always returns the optimal route.

Cost: with a binary heap, O((V + E) log V). On a grid each cell has at most 8 edges, so this is about O(V log V) for V cells. For the 2,240-cell floor that is a few milliseconds.

Why the project uses it twice: to choose a goal, the robot needs the route distance to every candidate. One Dijkstra run from the robot, without a goal, gives exactly that (the "distance field"). With the Dijkstra planner selected, the route to the chosen goal is simply read back from that same field, so no second search is needed.

9.3 A* (Hart, Nilsson & Raphael, 1968)

A* is Dijkstra with a sense of direction. It orders the queue by f = g + h, where h(n) is an estimate of the remaining cost to the goal. The project uses the octile distance, the exact cost on an empty 8-connected grid:

h(n) = max(dx, dy) + (√2 − 1) · min(dx, dy)

This h is admissible (it never overestimates, because walls can only make routes longer) and consistent (it never drops by more than the cost of one step). Those two properties guarantee that A* returns the same optimal route length as Dijkstra while expanding far fewer cells, because it stops wasting effort on cells that lead away from the goal. Ties on f are broken in favour of the larger g (the deeper node), which reaches the goal sooner. In Figure 9.1, A* expands 16 cells against Dijkstra's 21. On 40 random routes on the test ground it expands 87 cells on average against 974, 1.1 ms against 9 ms.

In simple words

Dijkstra spreads out like a ripple in a pond until it touches the goal. A* is a ripple that is pulled towards the goal: it still checks every place that could be on a shortest route, but ignores places that obviously are not.

9.4 RRT* (Karaman & Frazzoli, 2011)

Sampling-based planners do not search cell by cell. They grow a tree of straight line segments by throwing random points into the free space. That makes them the standard choice for robot arms and drones in continuous, high-dimensional spaces. The project's version combines three well-known improvements:

  1. Two trees grow, one from the robot and one from the goal, and try to connect after every new point (the RRT-Connect idea, Kuffner & LaValle 2000).
  2. RRT* rules: a new point is joined through whichever neighbour within radius r = γ·√(log n / n) gives it the cheapest cost from the root, and then nearby points are rewired through it if that shortens their cost. When a point gets cheaper, every point below it in the tree gets cheaper by the same amount, so the saving is propagated to its whole subtree. As samples grow, the tree's best route converges to the optimum.
  3. Informed sampling (Gammell et al., 2014): once a route of cost c exists, new samples are drawn only inside the ellipse |p − start| + |p − goal| ≤ c. Only there can a shorter route lie.

Every segment is checked against a fine collision mask (5 points per cell side, with a 0.3-cell safety margin at cell borders, so a line never squeezes diagonally between two obstacles). The final route is shortened along lines of sight, then drawn onto grid cells with Bresenham's line algorithm, whose 8-connected chain for a segment has exactly the octile length of that segment. If the route is not valid, or no route is found within 700 samples, the robot falls back to A* and the dashboard says so.

9.5 Ant Colony Optimisation (Dorigo, 1996)

Ants find short paths to food by laying pheromone: shorter paths are walked more often, collect more pheromone, and attract more ants. The planner imitates this with 10 virtual ants per round, for up to 12 rounds:

  • At cell i, an ant picks the next cell j with probability ∝ τjα · ηjβ (α = 1, β = 4), never revisiting a cell of its own walk and stepping back out of dead ends.
  • τj is the pheromone on j; ηj = 1 / (1 + detour), where detour = c(i, j) + h(j) − h(i) ≥ 0 is how much longer the move makes the best route still possible (h = octile distance). A move straight towards the goal has detour 0; a step backwards has up to 2√2.
  • After each round the pheromone evaporates by ρ = 30 %, every ant that arrived lays Q/L on its path (Q = 10, L its length, so shorter paths lay more), and the best path so far is reinforced again (the elitist ant system). The colony stops when the best path has not improved for 3 rounds.
Two corrections made during this project

RRT* used to trace its lines onto the grid cell by cell, turning every slanted line into a staircase (10 right and 3 down cost 13 instead of 11.24), so its routes were 18 % too long. The ants' first heuristic, η = 1/(step + distance to goal), barely distinguished neighbouring cells far from the goal ((41/40)4 ≈ 1.1), so the ants mostly wandered (25 % too long, 370 ms). Both were fixed, and the numbers below are after the fix. It is a good story for an interview: measure against a known optimum, find the cause, fix it, measure again.

Interview tip: "why Dijkstra and not A*?"

Don't say one is "better". Say: "Both give the optimal route on this grid. A* is faster for one point-to-point route because its admissible octile heuristic focuses the search. But to choose a goal I need distances to many candidates, and one Dijkstra run from the robot gives all of them at once. With Dijkstra as the planner, the route comes free from the same search. RRT* and ant colony are there for comparison; they suit continuous spaces and changing costs better than a small grid."
